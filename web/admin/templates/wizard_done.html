Wire it into a repo and your agents get persistent memory scoped to this project.

Connect a repo

Silo speaks the Model Context Protocol, so an agent calls it as tools — no file sync, no framework hooks.

1. Run a daemon for this project
# The token maps a bearer credential to exactly one project.
# Keep it secret — it is what scopes an agent to {{.Project}}.
silod --tokens "$SILO_TOKEN={{.Project}}" \
      --rqlite http://localhost:4001 \
      --admin-listen ./data/silod-admin.sock
2. Add .mcp.json to the repo
{
  "mcpServers": {
    "silo": {
      "command": "silo-mcp",
      "env": {
        "SILO_TOKEN": "${SILO_TOKEN}",
        "SILO_PROJECT": "{{.Project}}",
        "SILO_DAEMON_ADDR": "http://127.0.0.1:8500"
      }
    }
  }
}

${SILO_TOKEN} is expanded from your shell environment at launch, so the token itself never lands in a file you might commit. Set it with export SILO_TOKEN=….

3. Restart the agent

It will discover four tools — silo_read, silo_write, silo_list, silo_search — and can then remember things across sessions.

What the agent can do

Anything it writes here survives the session that wrote it.

ToolPurpose
silo_read Recall a memory file written in an earlier session.
silo_write Store a memory file. Replaces the whole file, so read first.
silo_list Discover what has been remembered for this project.
silo_search Find a specific fact without reading everything.
